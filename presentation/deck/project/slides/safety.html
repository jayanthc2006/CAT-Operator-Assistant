SAY (45 s): "Safety is deliberately not machine learning. Readings go through deterministic rules, because stop/go decisions must be predictable and testable. Five live alerts: seatbelt, proximity, tilt, overspeed and engine temperature. Each one has a severity, a 'why' line with the actual value and threshold, and an action. One engineering detail we're proud of: the screen refreshes every two seconds, and a naive design logs the same alert every refresh. We found that in stress testing: the log went from 14 to 172 entries in a minute. Now we log on the transition, once when a condition starts, and again only if it clears and comes back. Worker plus tilt held for a minute gives exactly two entries." KNOW: Thresholds: seatbelt open = red; proximity < 3 m red STOP, 3–6 m amber; tilt > 15° red; speed > site limit amber (Excavator 6, Wheel Loader 25, Dozer 10, Artic Truck 40, Grader 30 km/h); engine coolant > 98 °C amber. In normal simulated operation no alert fires (objects ≥ 7 m, tilt ≈ 4°). Tests: 13 alert-log checks (worker held → 1, tilt held → 1, clear + re-enter → 2, worker + tilt → 2). No live overload alert (overload exists only in history). IF ASKED "What about false alarms?": "In normal simulated operation nothing fires, there are caution and stop bands, and each event logs once. On real sensors we'd add debounce and sensor-fault checks."
