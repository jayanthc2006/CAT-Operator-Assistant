SAY (40 s): "The whole thing runs on the device. Telemetry comes in, today from our simulator, later from a CAN/J1939 or telematics adapter. Python holds the logic, SQLite stores everything locally, and the analytics layer holds the two ML models, the safety rules and the training loop. Streamlit renders the operator screens in an Edge app window. Only two things touch the internet, and both are optional: YouTube lessons and Claude. If the network drops, nothing important changes. And Claude is not the decision-maker: our rule-based assistant pulls the facts from the app, and Claude, if a key is configured, only rephrases them." KNOW: No backend server; FastAPI is installed but unused. Models train in memory at startup (~30 s), are cached for the process and are not persisted. DB path via CAT_OPERATOR_DB; CAT_OFFLINE=1 forces offline. The terrain lesson is a local 42 s MP4 that plays offline; 4 other lessons are Cat® YouTube videos (key points + quiz still work offline). Claude call: claude-opus-5 with SDK server-side fallback; any error → the offline answer is shown. A real Claude call wasn't exercised in the audit (no key on the machine). IF ASKED "Why SQLite?": "Zero install, offline, a single file, enough for one machine. The data layer is isolated in data.py, so moving to a fleet database is a contained change."
